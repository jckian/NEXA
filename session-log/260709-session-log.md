## program-massing-shortfloor.html — free move (program massing) feature

- User request: let the user freely drag program massing groups in solid mode, snapped to 1×/⅔×/½× of the 8'-6" module (MODULE = 2.5908 m).
- Design (plan: `C:\Users\stu40\.claude\plans\idempotent-wishing-dahl.md`): post-build offset overlay — `MOVE_OFFSETS: Map<type,{dx,dy,dz}>` keyed by program **type**, so clicking any block moves that type's meshes across ALL floors together (incl. SHORT bricks). Offsets are applied to `mesh.position` only, never to `rec.cx/cy/cz` (shared with `exportBoxes`), and re-applied after every `build()` via a new `applyMoveOffsets()` call inserted right before `frameCamera(...)` — survives every rebuild (color/mode/core/ground/floor-height/protrude toggles) without touching `computeLayout`.
- Interaction: left-drag on a selected type = horizontal X/Z (raycast onto a horizontal plane through the grab point); `Shift`+drag = vertical Y (camera-facing vertical plane, switchable mid-drag); `Ctrl`/`Alt` held = temporary ⅔×/½× snap override; `1`/`2`/`3` keys or the new `#seg-move` UI segment set the default increment; arrow keys/`PageUp`/`PageDown` nudge the selected group; `Delete` clears one type's offset; `Esc`/click-on-background deselects; `Reset moves` button clears all. New `#move-readout` shows live offsets in module units.
- Core/corridor (`isCore`/`isCorridor`) are excluded from selection AND from offset application (`isMovable` gate now enforced inside `applyMoveOffsets()` and `exportOBJ`, not just at pointerdown-time) — closes a bug where the `?move=` URL debug hook could otherwise displace a core since it bypasses the pointerdown selection filter.
- `exportOBJ` (SHORT+LONG / LONG massing exports) now applies the same offsets to exported geometry. **Known limitation**: `exportKitOBJ`/`exportSkinOBJ` (FRAME/INFILL/SKIN) walk `SHORT_PLACE` placement lists that carry no program-type tag, so those three exports do NOT reflect manual moves — future work if needed.
- Headless verification hook: `?move=type:dx,dy,dz;type2:...` (module units, `decodeURIComponent`'d type names) added to the existing URL-param block; `window.__DEBUG__` gained `MOVE_OFFSETS`, `SELECTED`, `applyMoveOffsets`, `setSelected`.
- Backup: `BACKUP/program-massing-shortfloor-260709-preMove.html`.
- Verified via local-server + headless-Edge screenshots: baseline (no `?move`) unchanged vs backup; `?move=exhibition%20gallery:4,0,4` visibly displaces that SHORT program group with a gap left behind; `?move=fire%20stair%20&%20passenger%20elevator%20core%20a:4,0,4` — **after the isMovable fix** — renders identical to baseline (core correctly immovable even via the URL hook); structure mode (`?mode=structure`) unaffected.
